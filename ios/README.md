# Cooking be easy — iOS app

A native iPhone app that wraps the deployed site at
https://cooking-be-easy.vercel.app.

It is deliberately a shell, not a port. The recipe library, the AI ingredient
extraction, the pricing lookups and the household sharing all run server-side in
the Next.js app, so there is nothing to reimplement in Swift and nothing to keep
in sync — ship the web app and the phone has it. What the shell adds is the
handful of things a web page on iOS cannot do for itself:

| | |
|---|---|
| **Google sign-in** | Google refuses OAuth inside an embedded web view, so the shell lifts sign-in into a real Safari session (`ASWebAuthenticationSession`) and carries the auth code back over the `cookingbeeasy://` scheme. |
| **Timer notifications** | A web view has no Notification API at all. The shell mirrors the cooking timers as iOS local notifications, so they still go off with the app closed and the phone in your pocket. |
| **`confirm()` dialogs** | A web view silently discards JavaScript dialogs unless the host handles them, which would quietly break every delete confirmation on the site. |
| **Camera and photos** | Native pickers, with the usage strings iOS requires. |
| **Home screen presence** | Icon, launch screen, offline retry screen, pull to refresh, swipe-back. |

The web half of the contract lives in [`lib/native.ts`](../lib/native.ts) — the
user-agent tag, the URL scheme and the timer message handler name are shared
constants, and changing one means changing the other.

## Build and install

The app talks to production, so the phone needs a network connection but your
Mac does not need the dev server running.

```bash
open ios/CookingBeEasy.xcodeproj
```

Pick your iPhone in the toolbar and hit Run. Signing is automatic against team
`82WADWVR5Y`.

From the command line instead:

```bash
xcodebuild -project ios/CookingBeEasy.xcodeproj -scheme CookingBeEasy -destination 'generic/platform=iOS' -allowProvisioningUpdates
```

The first install on a new phone needs Developer Mode turned on, under
**Settings → Privacy & Security → Developer Mode**.

Builds signed with a paid Apple Developer account last a year before iOS stops
launching them; rebuild and reinstall to reset the clock.

## Project layout

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen)
from `project.yml`, and the generated `.xcodeproj` is committed so you can open
it without installing anything. If you change the project itself — new files are
picked up automatically, so this mostly means build settings:

```bash
brew install xcodegen && (cd ios && xcodegen generate)
```

```
CookingBeEasy/
  App/      AppConfig.swift — the shared constants and the URL rules
  Web/      WebAppViewController.swift — the web view and everything around it
  Timers/   TimerNotifications.swift — cooking timers as local notifications
Tools/      generate-assets.swift — regenerates the icon from app/apple-icon.png
```

## Changing the icon

The icon is generated from the web app's `app/apple-icon.png` so the two cannot
drift:

```bash
swift ios/Tools/generate-assets.swift
```
